# studio-observable-codegen

## Change Contract

- **Responsibility:** Pure generation of observable TypeScript models and resource facades from Rust metadata and OpenAPI components.
- **Public interface:** `ObservableModel::of<T>` / `named`, `ObservableCollection::of<T>` / `named`, `ObservableResource::of<T>` / `named` / `mapped` / `collections`, `ObservableArg`, `render` / `render_fields`, and typed `GenerationError` diagnostics. Named metadata references existing owned schema components; it defines no new wire DTO.
- **Boundaries:** No runtime, HTTP, persistence, filesystem, or process dependencies. `studio-contracts` registers owners, formats output and checks drift.
- **Invariants:** Only reachable closed objects, scalar leaves, nullable values, arrays and string-tagged object unions are supported. Other shapes fail with their schema path. Identity and ordering fields must be required strings; opaque fields must exist. Ordered collections retain a shallow observable array and model identities, updating fields in place and removing/inserting only absent, new or reordered rows. Ordering uses the declared key, then identity to break ties. Equal replay performs no array mutations or reactions, including empty collections. Public data derives from generated DTOs and is deeply readonly; mutable models stay private. A module can mix selected collection resources and typed object, array, scalar or union roots. Array/list mirrors start empty; other roots require an initial DTO. Each mirror exposes a readonly `current` and delegates `apply` to the same model inside `runInAction`.
- **Reconciliation cost:** A full snapshot requires a linear scan. Scalar-only changes perform no array operations; each new/deleted row performs one splice, and each changed ordering key performs two. Initial population sorts once. Native array shifts still cost linear time per insertion/removal; the generator keeps no extra persistent index or tree.
- **Selected collections:** A singleton array resource can expose readonly maps selected by existing payload collection tags. Generation validates the resource array item reference, selected tag/value schema and required string envelope identity. Keys come from the payload envelope, including workspace values without an `id` field. Unselected variants are never modeled. Each projection has its own cached slot and status; multiple projections share the same resource subscription and eviction identity. Requests and question history use separate projections so sidebar state readers construct no approval models. Mirrors accept the unchanged payload union array. Duplicate selected keys fail before any collection changes. Collection adapters coexist with argument resources in the same module without extra network interests.
- **Configuration owner:** Rust registration in `runtime-schema/src/observable_resources.rs`. Production selects agents, projects, peer teams, workspaces and agent tails from the existing `state` resource. Lead-only tail selection is owned by the server, not filtered again in the generator. Rust-owned `track_nested` metadata selects rendered nested models; other nested values are cloned deeply frozen plain refs with structural equal-replay identity. `declared_fields` reads an open record’s declared properties from that same schema owner; its pure DTO types are emitted into `observableFieldTypes.ts`, avoiding store dependencies in wire-only consumers. Branded argument representation and omission derive from ResourceRef. Generated facades delegate keyed caching and bounded inactive eviction to the store runtime through `runtime.keyed`; acquisition remains scoped to observation. The production singleton drops its graph through the existing subscription cache eviction callback.
- **Collection inventory:** `render_entity_collections` derives names and typed empty maps from the Rust-owned `SyncEntityPayload` union. Each collection resource also emits its selected entity union and serialization function; consumers keep no parallel collection lists. `WorkSubscriptionData` describes the existing root-scoped work projection including evidence and domain acceptance policy. Terminal metadata/output reuse their existing keyed transports. Retained cleanup records use a lead-scoped entity resource that includes deleted members until cleanup completes.
- **Object composition:** Object `allOf` members merge properties and required fields. Conflicting declarations fail with the member schema path; unsupported compositions remain errors. Declared-field root aliases consume the generated pure field types, preserving strict readonly facades over open transport records.
- **Focused checks:** `cargo test -j 4 --workspace --exclude studio-native-client --lib tests::`; TypeScript generator witnesses in repository-checks. After contract generation, `node workspaces/tooling/apps/repository-checks/tests/observable-codegen-witness.ts --production` compiles the committed production output under the web tsconfig and exercises all five maps through the mirror.
