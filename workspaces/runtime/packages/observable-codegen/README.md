# studio-observable-codegen

## Change Contract

- **Responsibility:** Pure generation of observable TypeScript models and resource facades from Rust metadata and OpenAPI components.
- **Public interface:** `ObservableModel::of<T>` / `named`, `ObservableCollection::of<T>` / `named`, `ObservableResource::of<T>` / `collections`, `ObservableArg`, `render`, and typed `GenerationError` diagnostics. Named metadata references existing owned schema components; it defines no new wire DTO.
- **Boundaries:** No runtime, HTTP, persistence, filesystem, or process dependencies. `studio-contracts` registers owners, formats output and checks drift.
- **Invariants:** Only reachable closed objects, scalar leaves, nullable values, arrays and string-tagged object unions are supported. Other shapes fail with their schema path. Identity and ordering fields must be required strings; opaque fields must exist. Ordered collections retain a shallow observable array and model identities, updating fields in place and removing/inserting only absent, new or reordered rows. Ordering uses the declared key, then identity to break ties. Equal replay performs no array mutations or reactions, including empty collections. Public data derives from generated DTOs and is deeply readonly; mutable models stay private. Resource roots are list objects of required arrays, so generated mirrors can start empty. Each mirror exposes a readonly `current` and delegates `apply` to the same model inside `runInAction`.
- **Reconciliation cost:** A full snapshot requires a linear scan. Scalar-only changes perform no array operations; each new/deleted row performs one splice, and each changed ordering key performs two. Initial population sorts once. Native array shifts still cost linear time per insertion/removal; the generator keeps no extra persistent index or tree.
- **Selected collections:** A singleton array resource can expose readonly maps selected by existing payload collection tags. Generation validates the resource array item reference, selected tag/value schema and required string envelope identity. Keys come from the payload envelope, including workspace values without an `id` field. Unselected variants are never modeled. The maps share one cached slot, status and observation interest; mirrors accept the unchanged payload union array. Duplicate selected keys fail before any collection changes. This adapter supports one singleton resource per generated module; list-root and argument facades remain covered by their separate fixtures.
- **Configuration owner:** Rust registration in `runtime-schema/src/observable_resources.rs`. Production selects agents, projects, peer teams, workspaces and agent tails from the existing `state` resource. Lead-only tail selection is owned by the server, not filtered again in the generator. Legacy open project folders, workspace notices and saved-order groups use explicit opaque reference fields; cloned opaque values are cloned, deeply frozen plain refs with structural equal-replay identity. Branded arguments are exercised by a fixture only; fixture argument facades retain their per-key slots. The production singleton drops its graph through the existing subscription cache eviction callback.
- **Focused checks:** `cargo test -j 4 -p studio-observable-codegen`; TypeScript generator witnesses in repository-checks. After contract generation, `node workspaces/tooling/apps/repository-checks/tests/observable-codegen-witness.ts --production` compiles the committed production output under the web tsconfig and exercises all five maps through the mirror.
