# Generated storage catalog

`runtime-state-schema.json` is generated from `canvas_schema::registry`,
`analytics_schema::registry` and `storage_catalog.rs`'s per-database SQL lists.
Unconverted Canvas tables live in `catalog-canvas.sql`, with additional Canvas
objects in `catalog-canvas-objects.sql`. `catalog-analytics.sql` retains only the
explicit revision triggers; Analytics table/index DDL belongs to its descriptors. Existing feature, receipt, cost,
dictionary, index, sync, durable, FTS and Supervisor owners are referenced directly.
Remaining raw entries preserve complete evolved layouts, dynamically constructed
SQL, or frozen dated-migration definitions. SQLite supplies names, object kinds,
creation order and SQL. FTS shadow tables and SQLite internal objects are excluded.

Analytics retains its own legacy migration-progress table DDL; it does not use
the Canvas descriptor's extra columns or status constraints. Top-level pragma
metadata comes from the shared writer durability policy. Feature preparation and
catalog generation use the same summary-delete trigger installer.

Regenerate after changing an owner:

```sh
STUDIO_WRITE_STORAGE_CATALOG=1 cargo nextest run --workspace --exclude studio-native-client --lib -j 4 -E 'package(=studio-runtime-store) & test(=canvas_schema::tests::generated_storage_catalog_matches_committed_json)'
```

Without the environment flag, this fast-tier test compares the generated bytes
with the committed file. It exports to disposable in-memory databases and never
opens live state. The storage-map tooling witness derives its complete source
table set from the generated catalog, including lazy tables and Supervisor.

When converting a raw owner to a descriptor, remove its raw SQL registration.
Duplicate unconditional declarations fail export. Historical migration fixtures remain
independent evidence; this generated catalog describes the current schema.
